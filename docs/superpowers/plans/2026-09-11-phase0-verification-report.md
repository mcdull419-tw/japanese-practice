## 0. 兩個交辦議題的處理

### 議題 1：golden file 產生條件與測試呼叫方式不一致

**現象**：`data/lessons/07.json`（golden file）原本是不帶 `--images` 產
生的（`images` 為空陣列）；`tests/extract/test_golden.py` 的兩個決定性
測試也是不帶 `--images` 呼叫 CLI。若把最終資料改成帶 `--images` 重新產
生（本任務要求的 `1-15 --images data/images --validate`），`07.json`
會多出 51 筆 `images`，但 golden 測試仍用不帶 `--images` 的方式重跑，
兩者就對不上，2 個 golden 測試會失敗（已實測重現）。

**選擇的作法**：golden file 與 CLI 標準呼叫一致，兩個決定性測試也改成
帶 `--images <暫存目錄>` 呼叫，讓「重跑管線」與「最終資料如何產生」用
的是同一組參數（見下一項議題後，這個暫存目錄可以跟 `data/images` 不同
仍能通過，因為 `file` 欄位已跟實際寫檔目錄解耦）。理由：spec §5.3 要求
「重跑管線必須能重現已提交的資料」，若最終資料含影像清單而回歸測試的
呼叫方式不含影像，測試等於沒有真正保護到「重跑最終指令會得到相同結
果」這件事——寧可讓測試呼叫方式跟著生產指令走，而不是讓生產資料遷就
測試的舊呼叫方式。

修改：`tests/extract/test_golden.py` 的
`test_cli_reproduces_golden_file`、
`test_cli_output_is_byte_identical_to_golden_file` 各自新增一個獨立暫存
目錄作為 `--images` 參數。

### 議題 2：`images[].file` 內容取決於 `--images` 參數值

**現象**：`tools/extract/images.py` 的 `extract_images()` 回傳的
`file` 欄位字面就是「輸出目錄 + 檔名」，也就是呼叫端傳入的 `--images`
值本身。同條件重跑位元組相同，但換一個輸出目錄，JSON 內容就變——JSON
內容因此取決於執行時的參數，不是純粹由 PDF 內容決定，這對「重跑必須
重現已提交資料」是一個潛在風險（今天資料是用 `data/images` 產生沒問
題，但任何人以後用不同目錄重跑，會產生看似「跟已提交資料不同」但其實
無害的差異，難以分辨是真的壞了還是只是路徑不同）。

**選擇的作法**：不改動 `tools/extract/images.py`（它有 21 個既有測試
直接依賴 `file` 是「實際可開啟的物理路徑」這個介面形狀，改動代價與風
險都不成比例，且 Task 11 已審過這個模組）。改在 `tools/extract/cli.py`
的 `extract_lesson()` 呼叫 `extract_images()` 之後，把回傳的 `file` 正
規化成固定 `data/images/<檔名>`——與規格 §4.5 範例、目錄結構 §6.4
（`data/images/ 課本插畫`）的既定慣例一致，且跟實際寫檔用的 `--images`
目錄完全解耦：物理檔案仍照呼叫端指定的目錄寫出（供算繪比對、人工核對
使用），但 JSON 內容本身不再受呼叫參數影響，兩次不同 `--images` 目錄
的呼叫在 JSON 層級會得到完全相同的結果。

已用重跑驗證：帶 `--images data/images` 與帶 `--images /tmp/anything`
分別跑第 7 課，`images` 欄位逐位元組相同（皆為 `data/images/07-p??-
??.png`），其餘欄位本來就相同。

## 6. 尚未解決的已知問題與影響範圍

1. **文法例句日中分界的退化案例**（`tools/extract/grammar.py`）：中文
   翻譯本身又引述一次日文原文時（例如「…"你好"用日語怎麼說？…是"こん
   にちは"。」這種結構），日中分界演算法會找到「只切出結尾句點」這種
   退化切法而拒絕接受，整行改判給 `jp`、`zh` 留空。**影響範圍**：全
   15 課 213 則文法例句中僅 1 則（第 7 課文法點 2 例句④），已在
   `grammar.py` 模組說明「已知限制」與 `_split_example_line` 函式說明
   中明確記錄。不影響任何不變式檢查（`zh` 允許為空，只有 `jp` 才要求
   非空）。
2. **第 2、13 課振假名配對率低於其餘課**（93.9%／95.6%，其餘課多在
   97.5%~100%）：第 13 課已由 Task 6 確認與歷史 mojibake bug 無關；第
   2 課成因未逐一核對。**影響範圍**：僅影響是否能自動產生「讀音」類
   題目的覆蓋率，不影響已產生內容的正確性（`pair_ruby` 設計原則是「配
   不到就不產生，不猜測」，見 `ruby.py` 模組說明）。
3. **`_TJ_ITEM` 不匹配 PDF `TJ` 陣列裡的字面字串**（`tools/extract/
   fragments.py`）：目前只影響頁尾頁碼，全 15 課驗證下沒有觸發正文遺
   漏，但這是抽取階段的風險，`validate_lesson` 無法檢測「本來還應該有
   更多內容卻沒被抽到」這類問題，只能驗證「已存在資料的自洽性」。若未
   來擴充到第 16~50 課且正文使用字面字串，需要重新評估。
4. **4 項 `--validate` 剩餘問題**（見第 3 節表格）：全部歸屬為課本原始
   版面或既有裁決下的正確行為，不需修正；`main()` 因此結束碼為 1，這
   是預期行為（此 CLI 呼叫方式下的「失敗」訊號其實是「誠實回報已知、
   已歸屬的版面特例」，不是抽取品質問題）。
