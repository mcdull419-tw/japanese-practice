## 4. 三份人工資料檔的規模與校對範圍

### `data/adjectives.json`（54 筆）

- な形 16 筆：由課本的 `［な］` 標記自動判定，可靠。
- い形 38 筆：草稿列出 55 個「以い結尾」的候選，人工剔除 17 個非形容詞——`先生`、`学生`、`何歳`、`はい`、`時計`、`何階`、`おととい`、`野菜`、`宿題`、`また いらっしゃって ください`、`妻／家内`、`だいたい`、`兄弟`、`どのぐらい`、`世界`、`お帰りなさい`、`経済`。
- 引用形處理三種課本寫法：`［な］` 標記、括號異寫（`いい （よい）` → 鍵取 `いい`，課次取第 8 課那筆）、並列寫法（`暑い、熱い` → 鍵取 `暑い`，`熱い` 的變化列入 alternatives）。

### `data/concepts.json`（81 個概念）

- 草稿來源：91 則 `grammar[]`。概念 id 人工命名（`p:ni:recipient`、`g:mou_mashita` 這類）。
- 純詞彙性質的條目（`どれ`、`何`、`～さん`、`お～`、`そうですか`）不建概念——那是單字，由 `w:` 概念涵蓋。
- **69 張有樣板的練習Ａ代入表全部歸屬到概念，fallback 題數為 0**。另外 9 張（`L04-A7`、`L06-A5`、`L08-A2`、`L12-A2`、`L12-A3`、`L13-A3`、`L14-A1` 等）課本抽取時 `template` 為 `None` 且 `rows` 為空，本來就不產題。
- 檔案不含 `skills` 欄位（規格 §13 決定 2），由 `test_conceptdefs.js` 的測試把關。

### `data/particles.json`（141 句、278 個標註）

- 素材限定 `文型` 與 `例文` 兩段落：`会話` 多為對話殘句（含說話者標籤），`問題` 是含題號與括號內答案的多行混合體，拆解屬 Phase 0 工作。
- 草稿以規則標出 295 個句末助詞，人工逐筆判定用法，並剔除 17 個非助詞的誤判：`いっしょに`、`ちょっと`、`とても`、`それから`、`これから`、`ずっと`、`あとで`、`全部で`、`住んで`（て形）等。
- 涵蓋 23 個概念。「這個 に 是哪種用法」全部由人工決定，規則只負責找出位置。
- 最關鍵的測試是 `at` 位置驗證：課本語料若重新抽取而位移，測試必須紅燈，而不是靜默把答案挖在別的字上。生成器執行期另有同樣的檢查作為第二道防線。

## 5. 待人工確認（我不能做的）

以下都需要在真實瀏覽器與真實使用中才看得出來，本報告不宣稱已驗證：

1. **代入題的長句輸入體驗**：答案動輒 20 字以上（`インドネシア人はスプーンと フォークで ごはんを 食べます。`），在手機上打完一句的實際負擔多大，會不會讓人放棄。
2. **挖空題的底線在手機上是否看得清楚**：題幹用全形底線 `＿`，在小螢幕與不同字型下是否一眼可辨。
3. **代入題答案的語序自由度實際有多常誤判**：日語語序自由，`はしで ごはんを 食べます` 與 `ごはんを はしで 食べます` 都對，但生成器只有一個標準答案。這會決定「我這樣寫也對」按鈕的按下頻率——若頻率很高，代表需要提前做 token 級比對，而不是留到 Phase 4。
4. **數量題的可接受讀音**：`7時間` 課本讀 `しちじかん`，但 `ななじかん` 也通行；目前 `alternatives` 為空，這類答案會被判錯。實際練習時是否造成困擾，需要使用後才知道。
5. **技能過濾的預設全開是否合理**：六類全開時一組 20 題裡各類的實際比例是否符合預期。

## 6. 已知限制

1. **練習Ｂ（107 則 drills）本次未納入**。計畫 Task 13 的停止條件是「實際產題的表數明顯低於 70 就停下回報」，實測只有 **16 / 107**。原因是計畫假設「`model_cue` 在 `model_answer` 中做單純字串替換」，但 77 則結構完整的練習Ｂ 中：20 則的 cue 是 `｜` 分隔的多組範例、35 則是含 `・` 與 `（）` 提示的複合 cue，只有 15 則的 cue 在答句中恰好出現一次。且能產題的那 16 則也有錯句——問答對只被替換了問句那半（`それは 何の 本ですか。 コンピューターの 雑誌です。`）。

   **後續（2026-09-26 定案，規格 §13 決定 7）**：練習Ｂ 排入 Phase 2b，作法是把它標註成練習Ａ 的形狀（template ＋ slots ＋ rows）後重用 `substitute.js`，而非寫解析器反推替換規則；標註正確性由「第 0 列填回 template 須逐字等於 `model_answer`」的往返測試自動把關。
2. **substitute 的複合題過度歸因**：一題的 `covers` 含句型概念與各槽位填充詞，答錯時全部計入（規格 §7.5 第 2 點）。token 級精準歸因屬 Phase 4。
3. **`会話` 與 `問題` 段落未納入 cloze 素材**（助詞與詞組挖空皆同），理由見第 4 節。
4. **量詞與時間的可接受讀音只有一個**：`alternatives` 為空，`ななじかん`、`しちねん`、`はちかい` 這類同樣正確的讀法會被判錯，需靠「我這樣寫也對」承接。
5. **形容詞的て形與副詞形產出但被擋掉**：`requires_lesson` = 16，課次範圍擴充到 16 課以上時自動生效，不需改程式。

## 7. 實作過程中對計畫的修正

以下都與計畫原稿不同，皆已補上對應測試：

| 項目 | 計畫原稿 | 實際 | 理由 |
|---|---|---|---|
| `counters.js` 的 `kai_times` | `S_SERIES` | `K_SERIES('かい','かい')` | 原稿 6回 會讀成 `ろくかい`，正確是 `ろっかい` |
| `counters.js` 的 `en`／`nen`／`jikan` | `PLAIN` | 數字讀法覆寫表 | 原稿 4円／4年／4時間 的 4 會讀 `よん`，正確是 `よ`；7時間／9時間 應為 `しち`／`く` |
| 詞組挖空的素材範圍 | 全部句子 | 限 `文型`／`例文` | 全語料實測產出 1697 題，含 `会話` 的說話者標籤被挖成「山」 |
| 詞組挖空的比對 | 由長到短取最長成功比對 | 額外要求其後接助詞或詞組結尾 | 否則 `山田` 被切成 `山`、`何時` 被切成 `何`；1697 題降為 271 題乾淨題 |
| 助詞挖空的 `EQUIVALENT` | `p:e:direction`／`p:ni:destination` | 增 `p:ni:source` ↔ `から` | 課本第 7 課文法 4 明教 `に`／`から` 皆可，但該句課本未標 `alt` |
| substitute 的範例列選擇 | 第 0 列，輪到第 0 列時用第 1 列 | 取「另一列中第一個有效者」 | 原稿在第 1 列越界時會連第 0 列的題目一起丟掉；計畫的「槽位越界」測試本身也因此無法通過（已改為三列測試） |
| substitute 的提示詞 | 全部槽位值 | 過濾空字串 | 課本某些列的槽位為空，否則題幹出現「あした ／ 」 |
| `adjectives.json` 的剔除清單 | 11 個 | 17 個 | 草稿實際還混進 `妻／家内`、`兄弟`、`世界`、`経済`、`どのぐらい` 等 |
| `test_adjectives_data.js` 的比對 | 切 `（` | 另切 `、，,／/` | 並列寫法 `暑い、熱い` 的鍵取第一個寫法，與 `transform.js` 一致 |
