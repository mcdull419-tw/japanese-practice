## 與計畫的偏差

### 1. 練習Ｂ 的作法在實作中被推翻兩次（規格決定 11）

計畫照決定 7 寫成「標註成練習Ａ 的形狀後重用 substitute，往返測試把關」。實作時把 98 則
全部標出來、**逐句讀過產出的句子**後發現：練習Ａ 是代入表，練習Ｂ 是變形練習，兩者結構不同。
純字串替換產出三到五成錯誤的日文（時態不一致、形容詞類別錯、はい／いいえ 與極性矛盾、
有生性用錯 あります／います、量詞不符、該連動的詞被寫死）。

決定 7 設計的往返測試擋不住這類錯——**它只驗第 0 列，而第 0 列永遠是對的**（那是課本原句）。

改為逐列人工書寫答案（使用者選擇的方案 C）。**答案必須能從課本文字判定**；答案在插畫裡的
（時鐘讀數、地圖位置、人物面板）一律不收，不憑空編造正解。98 則草稿中收 51 則。

教訓與決定 5 → 7 同一個：**「欄位齊備」「結構相似」都不等於「可用」，只有逐句讀過產出的
結果才算驗證過。** 這次是第二次踩到，兩次都是靠「產出實際句子拿來看」才發現。

### 2. 29 則插畫型練習Ｂ 的判定已於事前修正（規格決定 8）

決定 7 記為「Phase 0 抽取缺口」。算繪第 1 課第 4 頁確認：提示詞在人物面板插畫裡，文字層
只有佔位圖示，重抽也抽不到。已移出 2b，列入 Phase 4 與插畫關聯一起處理。

### 3. 新增題庫更正迴路（規格決定 12，使用者需求）

人工書寫的答案無法完全自動保證正確，因此新增「標記 → 匯出 → 更正」的路。這不在原計畫中，
是選定方案 C 後補上的配套。

### 4. 計畫中的 Task 11 往返測試被七道不變式取代

往返驗證的前提（template ＋ slots）已不存在。改為擋手寫失誤的機械不變式，其中最重要的是
**整列錯位偵測**——手寫 210 句時最可能發生、也最難用眼睛看出來的錯誤，因為錯位後兩句都是
通順的日文，只有對照提示詞才看得出來。

該偵測刻意放寬成「至少一個詞的詞頭出現在答案中」。嚴格的逐詞比對會被正常的詞形變化打敗
（帰ります → 帰って 語幹末音也變；釣りを します → 釣りに 行きます 動詞整個消失），
而一條會誤報的檢查最後只會被關掉，比放寬還糟。

### 5. `jp2zh` 的選項需要截短（計畫未預見）

課本中文欄有 126 筆夾著用法說明（「他，她，那個人 （ あの かた ）（…禮貌形）」）。整串當
選項會讓四個選項裡只有一個特別長——不必看懂也猜得到。已截到第一個全形括號之前；截短後
與同課別詞撞在一起者不當誘答，否則會出現兩個正確選項而其中一個被判錯。

### 6. 振假名詞典排除了兩類條目（計畫未預見）

- **數字的 ruby**（「3つ」標 みっ）：讀音依後接量詞而變（3つ みっつ／3人 さんにん／3階 さんがい），詞典硬套必錯。數量讀音由 `lang/numbers.js` 與 `counters.js` 負責。
- **夾假名的鍵**（読み方／生け花）：匹配只掃連續漢字段，這種鍵永遠匹配不到，收了只會讓詞典看起來比實際有用。

## 使用方式備忘

- **標記可疑題目**：答題結果畫面按「這題怪怪的」。不影響出題排程（`replay` 略過 `m='flag'` 事件）。
- **匯出待確認**：設定區「匯出待確認題目」，輸出含題幹、正解、出處、概念的 JSON。
- **回寫更正**：寫進 `data/corrections.json`，格式 `{"<item id>": {"answer": "…", "alternatives": ["…"], "prompt": "…"}}`，三個欄位皆選用。`alternatives` 是疊加而非取代。改完跑 `node --test "tests/app/*.js"`，孤兒更正會紅燈。
