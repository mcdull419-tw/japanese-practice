# Phase 3 同步 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 手機答題後，電腦重新整理就看到該筆紀錄；兩個裝置同時作答也不會遺失任何事件。

**Architecture:** 答題紀錄本來就是不可變事件、以 `(d, n)`（裝置 id＋序號）為唯一鍵，合併只是取聯集，所以同步不需要處理「衝突」，只需要處理「別人搶先寫入」。做法：把整份事件日誌存成 Gitea 私人 repo 裡的單一檔案 `progress.json`，用 Gitea contents API 讀寫，以 `sha` 當樂觀鎖：寫入失敗就重新拉取、合併、重試（上限 3 次）。同步邏輯寫成與網路無關的純函式，用假的 `fetch` 在 Node 測試；DOM 與瀏覽器 API 只留在薄薄的一層。

**Tech Stack:** 原生 ES modules、`node --test`、瀏覽器 `fetch`／IndexedDB、Gitea REST API v1。無新依賴。

**Spec:** `docs/superpowers/specs/2026-09-10-japanese-practice-design.md` §10.1（事件日誌）、§10.2（Store Adapter）、§10.3（Gitea 同步）、§13 Phase 3

## Global Constraints

- 事件唯一鍵是 `(d, n)`，**不是 `(i, t)`**（規格 §10.1 明文；§10.3 寫「以 `(i, t)` 去重」是規格內部矛盾，以 §10.1 與既有的 `mergeEvents` 為準）。合併一律呼叫 `app/core/store.js` 的 `mergeEvents`，不得另寫去重邏輯。
- 遠端單一檔案 `progress.json`，內容格式與 `exportJSON()` 相同：`{"version":1,"events":[...]}`。
- 讀：`GET /api/v1/repos/{owner}/{repo}/contents/progress.json` → base64 解碼 → 取得內容與 `sha`。寫：`PUT` 同路徑帶 `sha`（檔案不存在時 `POST` 建立）。
- 衝突重試上限 3 次。
- 認證用 personal access token，存於 IndexedDB，**不進版控、不寫死在程式中**，也不得出現在任何 `console.log`、錯誤訊息或測試輸出裡。Gitea 的 token 權限是「所有 repo」層級，無法限定單一 repo，因此 token 必須由**專用帳號**產生（見前置條件 3），不得用主帳號的 token。
- 啟動時**最多等同步 3 秒**再開始練習（否則重新整理後看不到另一台的紀錄）；超時或離線就用本機資料開始，不卡住。
- 觸發時機：session 結束、頁面隱藏（`visibilitychange`）、手動按鈕。離線時事件照常累積在本機，恢復連線後下一次同步一併補送；同步失敗**絕不能**讓答題畫面報錯或卡住。
- `app/core/` 不得碰全域 DOM／`window`；`fetch`、`indexedDB` 一律由呼叫端注入（沿用 `openStore(indexedDBFactory)` 的做法）。
- `app/` 下新增 `.js` 必須列入 `sw.js` 的 `PRECACHE`（`tests/app/test_sw.js` 把關）；改動上線內容後 `sw.js` 的 `CACHE` 版本號加一（目前 `jp-practice-v2` → `jp-practice-v3`）。
- 測試指令：`node --test "tests/app/*.js"`，全綠才算完成；CI 也跑這一條，紅燈不部署。
- git commit 訊息結尾加執行當下 session 指定的署名行（不要沿用別的模型名稱）。

## 前置條件（須使用者確認，Task 1 驗證）

網站在 `https://mcdull419-tw.github.io`，Gitea 在別的網域，所以：

1. Gitea 必須是 **HTTPS**（https 網站 fetch http 端點會被瀏覽器擋成 mixed content）。
2. Gitea `app.ini` 須開 CORS，且**允許 `Authorization` 標頭**——Gitea 預設的 `HEADERS` 只有 `Content-Type,User-Agent`，不含 `Authorization`，沒加的話所有帶 token 的請求都會在預檢（preflight）被擋：
   ```ini
   [cors]
   ENABLED = true
   ALLOW_DOMAIN = https://mcdull419-tw.github.io
   METHODS = GET,HEAD,POST,PUT,OPTIONS
   HEADERS = Authorization,Content-Type,User-Agent
   ```
   改完需重啟 Gitea。
3. 建一個**私人 repo**（例如 `japanese-progress`），建立時**勾選初始化（加 README）**——空 repo 在部分 Gitea 版本無法用 API 建立檔案。
   另開一個**專用 Gitea 帳號**（例如 `jp-sync`），只把它加為這個 repo 的協作者（寫入權限），用這個帳號產生 token（scope：`write:repository`）。token 會存在手機瀏覽器裡，用主帳號的 token 一旦外洩，所有私人 repo 都會曝光。
4. 使用者已確認：Gitea 從外網可以連到。

## Review Focus

規格沒寫、但最容易出事的情況：

1. **日文事件 id 的 base64**：事件的 `i` 欄位含日文（`conj:かきます:masu2te`），瀏覽器內建 `btoa` 遇到非 Latin-1 字元會直接丟例外。必須先轉 UTF-8 位元組再 base64，解碼反向。對應 Task 2。
2. **瀏覽器 HTTP 快取吃掉 `sha`**：`GET` 若被快取，拿到舊 `sha`，之後每次 `PUT` 都被當成衝突。讀取必須 `cache: 'no-store'`。對應 Task 2。
3. **Gitea 對「沒有權限的私人 repo」回 404，不回 403**：讀到 404 不能直接當成「檔案還不存在」——token 錯或 repo 名拼錯時也是 404。新裝置本機沒紀錄時根本不會寫入，錯誤設定會被顯示成「已同步」。因此檔案 404 時，`read()` 再查一次 repo 本身：repo 也 404 才丟「找不到 repo 或沒有權限」。對應 Task 2。
4. **衝突時 Gitea 回傳的狀態碼不固定**（409／422／500 都見過）：不能靠狀態碼判斷「被搶先」。改成「寫入失敗後重新讀一次，`sha` 變了才算被搶先，沒變就是真的失敗，直接丟出」。對應 Task 3。
5. **遠端檔案被手動改壞**（不是合法 JSON）：絕不能把它當成空檔案然後用本機內容覆蓋——那會抹掉另一台裝置所有的紀錄。必須報錯並停止。對應 Task 2。
6. **同步中途離線／同時按兩次**：`fetch` 丟 `TypeError` 要轉成「離線，稍後再試」；但 CORS 沒設好在瀏覽器裡也是 `TypeError`，所以要看 `navigator.onLine` 區分「離線」與「網路正常卻連不上（多半是 CORS 或網址）」，否則設定階段會被誤導。同步進行中再觸發應共用同一個進行中的同步，不是平行跑兩個。對應 Task 5。
7. **Service Worker 攔截跨網域請求**：`sw.js` 目前對所有 GET 都 `cache-first`，Gitea 的 GET 也會經過它。雖然 Gitea 的網址不在快取清單裡、最終會落到網路，但這是靠運氣；明確跳過跨網域請求。對應 Task 5。
8. **IndexedDB 升版**：新增 token 的儲存空間要把資料庫版本從 1 升到 2；升版時**不得動到既有的 `events` 儲存空間**，否則使用者的全部答題紀錄會消失。對應 Task 4。
9. **升版被舊分頁擋住**：只要還有舊版分頁（例如加入主畫面的 PWA）開著，`open(…, 2)` 會觸發 `blocked` 且一直不完成，畫面永遠停在「載入中」。而且 `openStore` 遇錯會退回 `MemoryStore`——若把「被擋住」也當一般錯誤，答題紀錄會只存在記憶體、關掉就消失。必須：被擋住時丟專用錯誤、`openStore` **不得**對它退回記憶體、畫面請使用者關閉其他分頁；並從這版起讓連線在 `versionchange` 時自行關閉，下次升版不再被擋。對應 Task 4。
10. **啟動同步沒等完就開始練習**：`runSession` 一開始就讀本機事件，若同步還在等 Gitea 回應，儀表板與選題用的是舊資料——「重新整理就看到另一台的紀錄」這個目標本身就失敗。對應 Task 5。

### Task 1: 前置條件檢查腳本

**Files:**
- Create: `tools/check-gitea.sh`

**Interfaces:**
- Produces: `bash tools/check-gitea.sh <GITEA_BASE_URL> <OWNER> <REPO>`，檢查全過 exit 0，任一失敗 exit 1 並說明哪一項沒過。token 從環境變數 `GITEA_TOKEN` 讀，沒設就**不回顯地**提示輸入（不放命令列參數，免得留在 shell 歷史與 `ps` 裡），**不得印出**。

- [ ] **Step 1: 寫腳本**

```bash
#!/usr/bin/env bash
# 同步前置條件檢查（Phase 3）。用法：bash tools/check-gitea.sh https://git.example.com OWNER REPO
# token 不放參數（會留在 shell 歷史）：沒設 GITEA_TOKEN 就提示輸入，輸入時不顯示。
set -u
BASE="${1:?用法: check-gitea.sh BASE_URL OWNER REPO}"; OWNER="${2:?}"; REPO="${3:?}"
TOKEN="${GITEA_TOKEN:-}"
if [ -z "$TOKEN" ]; then read -rsp "Gitea token（輸入時不顯示）: " TOKEN; echo; fi
ORIGIN="https://mcdull419-tw.github.io"
REPO_URL="${BASE%/}/api/v1/repos/${OWNER}/${REPO}"
URL="${REPO_URL}/contents/progress.json"
fail=0
case "$BASE" in https://*) echo "OK   HTTPS";; *) echo "FAIL 不是 HTTPS（https 網站會擋 mixed content）"; fail=1;; esac

hdr=$(curl -s -o /dev/null -D - -X OPTIONS "$URL" \
  -H "Origin: $ORIGIN" -H "Access-Control-Request-Method: PUT" \
  -H "Access-Control-Request-Headers: authorization,content-type")
echo "$hdr" | grep -qi "^access-control-allow-origin: *\(${ORIGIN}\|\*\)" \
  && echo "OK   CORS 放行 $ORIGIN" || { echo "FAIL CORS 沒放行 $ORIGIN（app.ini [cors] ALLOW_DOMAIN）"; fail=1; }
echo "$hdr" | grep -i "^access-control-allow-headers" | grep -qi "authorization" \
  && echo "OK   CORS 放行 Authorization 標頭" || { echo "FAIL CORS 沒放行 Authorization（app.ini [cors] HEADERS 要加 Authorization）"; fail=1; }
echo "$hdr" | grep -i "^access-control-allow-methods" | grep -qi "PUT" \
  && echo "OK   CORS 放行 PUT" || { echo "FAIL CORS 沒放行 PUT（app.ini [cors] METHODS）"; fail=1; }

# 先查 repo 本身：檔案 404 分不出「還沒建立」與「repo 名錯／沒權限」，repo 端點分得出來。
resp=$(curl -s -w $'\n%{http_code}' -H "Authorization: token ${TOKEN}" "$REPO_URL")
code="${resp##*$'\n'}"; body="${resp%$'\n'*}"
case "$code" in
  200)
    echo "OK   token 看得到 repo"
    echo "$body" | grep -q '"push":true' \
      && echo "OK   token 有寫入權限" || { echo "FAIL token 只能讀、不能寫（專用帳號要設為協作者並給寫入權限，token scope 要 write:repository）"; fail=1; }
    echo "$body" | grep -q '"empty":true' \
      && { echo "FAIL repo 是空的（在 Gitea 網頁加一個 README，空 repo 可能無法用 API 建檔）"; fail=1; } || echo "OK   repo 已初始化"
    ;;
  404) echo "FAIL 找不到 repo：名稱拼錯，或 token 的帳號沒有權限（Gitea 對無權限的私人 repo 回 404）"; fail=1;;
  401|403) echo "FAIL token 無效或權限不足 ($code)"; fail=1;;
  *) echo "FAIL 查 repo 時非預期狀態碼 $code"; fail=1;;
esac

code=$(curl -s -o /dev/null -w "%{http_code}" -H "Authorization: token ${TOKEN}" "$URL")
case "$code" in
  200) echo "OK   progress.json 已存在";;
  404) echo "OK   progress.json 還沒建立（第一次同步時會建立）";;
  *) echo "FAIL 讀 progress.json 時非預期狀態碼 $code"; fail=1;;
esac
exit $fail
```

```js
import { test } from 'node:test';
import assert from 'node:assert/strict';
import { utf8ToBase64, base64ToUtf8, makeGiteaClient, GiteaError } from '../../app/core/gitea.js';

const ev = (d, n, i = 'conj:かきます:masu2te') => ({ d, n, i, t: 1000 + n, g: 3, r: 100, m: 'text' });

/** 假的 fetch：記錄請求，依序回傳預先安排的回應。 */
function fakeFetch(responses) {
  const calls = [];
  const fn = async (url, init = {}) => {
    calls.push({ url, init });
    const r = responses.shift();
    if (r instanceof Error) throw r;
    return { status: r.status, ok: r.status >= 200 && r.status < 300, json: async () => r.body };
  };
  fn.calls = calls;
  return fn;
}
const mk = (fetchFn) => makeGiteaClient({
  baseUrl: 'https://git.example.com/', owner: 'me', repo: 'prog', token: 'SECRET', fetchFn,
});

test('base64 對日文往返不失真（btoa 對非 Latin-1 會丟例外）', () => {
  const s = JSON.stringify({ i: 'conj:かきます:masu2te', z: '送って' });
  assert.equal(base64ToUtf8(utf8ToBase64(s)), s);
});

test('base64 對一年份的事件量（約 2 萬筆）不爆堆疊', () => {
  const big = JSON.stringify(Array.from({ length: 20000 }, (_, n) => ev('a', n)));
  assert.equal(base64ToUtf8(utf8ToBase64(big)), big);
});

test('read：檔案 404、repo 存在 → null（檔案還沒建立）', async () => {
  const f = fakeFetch([{ status: 404, body: {} }, { status: 200, body: {} }]);
  assert.equal(await mk(f).read(), null);
  assert.equal(f.calls[1].url, 'https://git.example.com/api/v1/repos/me/prog');
  assert.equal(f.calls[1].init.headers.Authorization, 'token SECRET');
});

test('read：檔案 404、repo 也 404 → 丟 404（repo 名錯或沒權限，不可當成「還沒建立」）', async () => {
  const f = fakeFetch([{ status: 404, body: {} }, { status: 404, body: {} }]);
  await assert.rejects(() => mk(f).read(), (e) => e instanceof GiteaError && e.status === 404);
});

test('read：解碼內容與 sha；請求帶 token、網址正確、不吃瀏覽器快取', async () => {
  const events = [ev('a', 1)];
  const content = utf8ToBase64(JSON.stringify({ version: 1, events }));
  const f = fakeFetch([{ status: 200, body: { sha: 'abc', content } }]);
  const out = await mk(f).read();
  assert.deepEqual(out, { sha: 'abc', events });
  const { url, init } = f.calls[0];
  assert.equal(url, 'https://git.example.com/api/v1/repos/me/prog/contents/progress.json');
  assert.equal(init.headers.Authorization, 'token SECRET');
  assert.equal(init.cache, 'no-store', '否則舊 sha 會讓之後每次寫入都被當成衝突');
});

test('read：Gitea 的 base64 帶換行也能解', async () => {
  const content = utf8ToBase64(JSON.stringify({ version: 1, events: [] })).replace(/(.{20})/g, '$1\n');
  const f = fakeFetch([{ status: 200, body: { sha: 's', content } }]);
  assert.deepEqual((await mk(f).read()).events, []);
});

test('read：遠端內容不是合法 JSON → 丟錯，不當成空檔案（否則會用本機覆蓋掉別台的紀錄）', async () => {
  const f = fakeFetch([{ status: 200, body: { sha: 's', content: utf8ToBase64('{壞掉') } }]);
  await assert.rejects(() => mk(f).read(), (e) => e instanceof GiteaError && e.status === null);
});

test('read：401／403／500 丟 GiteaError 並帶狀態碼', async () => {
  for (const status of [401, 403, 500]) {
    const f = fakeFetch([{ status, body: {} }]);
    await assert.rejects(() => mk(f).read(), (e) => e instanceof GiteaError && e.status === status);
  }
});

test('read：網路錯誤原樣丟出（讓上層判斷離線）', async () => {
  const f = fakeFetch([new TypeError('Failed to fetch')]);
  await assert.rejects(() => mk(f).read(), TypeError);
});

test('write：有 sha 用 PUT 並帶 sha；沒有 sha 用 POST 且不帶 sha', async () => {
  const f = fakeFetch([{ status: 200, body: {} }, { status: 201, body: {} }]);
  const c = mk(f);
  await c.write([ev('a', 1)], 'abc', 'sync');
  await c.write([ev('a', 1)], null, 'sync');
  assert.equal(f.calls[0].init.method, 'PUT');
  assert.equal(JSON.parse(f.calls[0].init.body).sha, 'abc');
  assert.equal(f.calls[1].init.method, 'POST');
  assert.equal('sha' in JSON.parse(f.calls[1].init.body), false);
  const sent = base64ToUtf8(JSON.parse(f.calls[0].init.body).content);
  assert.deepEqual(JSON.parse(sent), { version: 1, events: [ev('a', 1)] });
});

test('錯誤訊息與狀態不會洩漏 token', async () => {
  const f = fakeFetch([{ status: 401, body: {} }]);
  await assert.rejects(() => mk(f).read(), (e) => !String(e.message).includes('SECRET'));
});

/**
 * Gitea contents API 用戶端（規格 §10.3）。只管單一檔案 progress.json 的讀與寫，
 * 不做合併、不做重試——那是 sync.js 的事。fetch 由呼叫端注入，本檔不碰全域。
 */

/** UTF-8 安全的 base64。btoa 只吃 Latin-1，事件 id 含日文會直接丟例外。 */
export function utf8ToBase64(str) {
  const bytes = new TextEncoder().encode(str);
  let bin = '';
  // 分段轉換：一次 spread 整個陣列在事件量大時會爆呼叫堆疊。
  for (let i = 0; i < bytes.length; i += 0x8000) {
    bin += String.fromCharCode(...bytes.subarray(i, i + 0x8000));
  }
  return btoa(bin);
}

export function base64ToUtf8(b64) {
  const bin = atob(b64.replace(/\s/g, ''));
  const bytes = Uint8Array.from(bin, (c) => c.charCodeAt(0));
  return new TextDecoder().decode(bytes);
}

export class GiteaError extends Error {
  constructor(message, status = null) {
    super(message);
    this.name = 'GiteaError';
    this.status = status;
  }
}

export function makeGiteaClient({ baseUrl, owner, repo, token, path = 'progress.json', fetchFn }) {
  const repoUrl = `${baseUrl.replace(/\/+$/, '')}/api/v1/repos/${encodeURIComponent(owner)}`
    + `/${encodeURIComponent(repo)}`;
  const url = `${repoUrl}/contents/${path.split('/').map(encodeURIComponent).join('/')}`;
  const headers = { Authorization: `token ${token}`, 'Content-Type': 'application/json' };

  return {
    /** 回 { sha, events }；檔案不存在回 null；網路錯誤（TypeError）原樣丟出。 */
    async read() {
      // no-store：被瀏覽器快取的舊回應會帶舊 sha，之後每次寫入都被當成衝突。
      const res = await fetchFn(url, { headers, cache: 'no-store' });
      if (res.status === 404) {
        // Gitea 對「repo 名錯／token 沒權限」也回 404。不查 repo 的話，新裝置本機沒紀錄時
        // 根本不會寫入，錯誤設定會被顯示成「已同步」。
        const repoRes = await fetchFn(repoUrl, { headers, cache: 'no-store' });
        if (repoRes.ok) return null;
        throw new GiteaError(`找不到 repo 或沒有權限（${repoRes.status}）`, repoRes.status);
      }
      if (!res.ok) throw new GiteaError(`讀取失敗（${res.status}）`, res.status);
      const body = await res.json();
      let parsed;
      try {
        parsed = JSON.parse(base64ToUtf8(body.content));
      } catch {
        // 不當成空檔案：那會讓本機內容覆蓋掉遠端（可能是另一台裝置全部的紀錄）。
        throw new GiteaError('遠端 progress.json 內容不是合法 JSON，已停止同步以免覆蓋');
      }
      return { sha: body.sha, events: Array.isArray(parsed.events) ? parsed.events : [] };
    },

    /** sha 為 null 表示檔案尚不存在（POST 建立），否則 PUT 更新。 */
    async write(events, sha, message) {
      const content = utf8ToBase64(JSON.stringify({ version: 1, events }));
      const res = await fetchFn(url, {
        method: sha ? 'PUT' : 'POST',
        headers,
        body: JSON.stringify(sha ? { content, sha, message } : { content, message }),
      });
      if (!res.ok) throw new GiteaError(`寫入失敗（${res.status}）`, res.status);
    },
  };
}

/**
 * 同步（規格 §10.3）。事件不可變、以 (d,n) 為鍵，合併 = 取聯集，因此「衝突」不存在，
 * 只有「別人搶先寫入」：遠端 sha 變了。處理方式是重新拉取、合併、再寫。
 *
 * 判斷「被搶先」不靠 HTTP 狀態碼（Gitea 對 sha 不符回過 409／422／500），
 * 而是寫入失敗後重新讀一次：sha 變了才是被搶先，沒變就是真的失敗，直接丟出。
 */
import { mergeEvents } from './store.js';

const keyOf = (e) => `${e.d}#${e.n}`;

export async function syncEvents(local, client, { maxAttempts = 3, message = 'sync' } = {}) {
  let pulled = 0;
  for (let attempt = 0; attempt < maxAttempts; attempt++) {
    const remote = await client.read();          // 網路錯誤、壞檔在這裡丟出，本機不受影響
    const localEvents = await local.allEvents();
    const remoteEvents = remote ? remote.events : [];
    const merged = mergeEvents(localEvents, remoteEvents);

    const localKeys = new Set(localEvents.map(keyOf));
    const remoteKeys = new Set(remoteEvents.map(keyOf));
    const freshForLocal = merged.filter((e) => !localKeys.has(keyOf(e)));
    const newForRemote = merged.filter((e) => !remoteKeys.has(keyOf(e))).length;

    // 只寫新增的：事件不可變，已有的重寫一次只是白做（一年約 2 萬筆）。
    if (freshForLocal.length) { await local.appendEvents(freshForLocal); pulled += freshForLocal.length; }
    // 遠端已經有全部，或兩邊都空（不建立空檔案）：不寫，避免無意義的 commit。
    if (!newForRemote && (remote || merged.length === 0)) return { pulled, pushed: 0 };

    try {
      await client.write(merged, remote ? remote.sha : null, message);
      return { pulled, pushed: newForRemote };
    } catch (err) {
      const now = await client.read();
      if ((now ? now.sha : null) === (remote ? remote.sha : null)) throw err;   // 不是被搶先
    }
  }
  throw new Error(`同步重試次數用盡（${maxAttempts} 次都被別的裝置搶先寫入），稍後再試`);
}

/** 規格 §10.2：包裝 LocalStore，額外做遠端合併。makeClient() 回 null 表示尚未設定同步。 */
export class GiteaStore {
  constructor(local, makeClient) {
    this._local = local;
    this._makeClient = makeClient;
  }
  appendEvents(evs) { return this._local.appendEvents(evs); }
  allEvents() { return this._local.allEvents(); }
  exportJSON() { return this._local.exportJSON(); }
  importJSON(s) { return this._local.importJSON(s); }
  getMeta(k) { return this._local.getMeta(k); }
  setMeta(k, v) { return this._local.setMeta(k, v); }
  async sync() {
    const client = await this._makeClient();
    if (!client) return { pulled: 0, pushed: 0, skipped: true };
    return syncEvents(this._local, client);
  }
}
```

```js
// 同步控制器與設定區的同步段落（規格 §10.3）。控制器是純邏輯，可在 Node 測試；
// renderSyncSection 才碰 DOM，與 settings.js 的做法一致。
import { makeGiteaClient, GiteaError } from '../core/gitea.js';

const META_KEY = 'gitea';

export const isConfigured = (c) => !!(c && c.baseUrl && c.owner && c.repo && c.token);

export async function loadSyncConfig(store) { return (await store.getMeta(META_KEY)) || null; }
export async function saveSyncConfig(store, cfg) { await store.setMeta(META_KEY, cfg); }

/**
 * 一句話給使用者看。不含 token，也不回顯原始例外訊息（可能夾帶網址或標頭）。
 * fetch 的 TypeError 同時代表「離線」與「CORS 被擋」，瀏覽器不給細節，只能靠
 * navigator.onLine 分辨——設定階段若一律說「離線」，會讓人去查錯地方。
 */
export function describeSyncError(err, { online = true } = {}) {
  if (err instanceof TypeError) {
    return online
      ? '連不上 Gitea（網路正常——多半是 Gitea 的 CORS 設定或網址有誤）；紀錄仍保存在這台裝置上'
      : '離線中，恢復連線後會自動補送（紀錄仍保存在這台裝置上）';
  }
  if (err instanceof GiteaError) {
    if (err.status === 401) return 'token 無效，請重新產生並貼上';
    if (err.status === 403) return 'token 權限不足（需要該 repo 的讀寫）';
    if (err.status === 404) return '找不到 repo，或 token 沒有權限（Gitea 對無權限的私人 repo 也回 404）';
    if (err.status === null) return err.message;
    return `Gitea 回應錯誤（${err.status}）`;
  }
  if (/重試次數用盡/.test(String(err && err.message))) return '別的裝置同時在寫入，稍後再試';
  return '同步失敗，稍後再試';
}

export function makeSyncController({ store, onStatus, isOnline = () => true }) {
  let inflight = null;
  return {
    isBusy: () => inflight !== null,
    syncNow() {
      if (inflight) return inflight;                      // 同時觸發共用同一次，不平行跑兩個
      inflight = (async () => {
        try {
          const r = await store.sync();
          // 練習進行中拉到的紀錄，本輪的儀表板與選題不會重算（events 是 runSession 開頭讀的）。
          const later = r.pulled ? '，下一組練習起生效' : '';
          onStatus(r.skipped
            ? { ok: true, text: '尚未設定同步' }
            : { ok: true, text: `已同步（收到 ${r.pulled} 筆，送出 ${r.pushed} 筆${later}）` });
          return r;
        } catch (err) {
          onStatus({ ok: false, text: describeSyncError(err, { online: isOnline() }) });
          return null;                                    // 答題畫面不該因為同步失敗而壞掉
        } finally {
          inflight = null;
        }
      })();
      return inflight;
    },
  };
}

/**
 * 啟動時用：最多等 ms 毫秒。不等的話 runSession 會在同步完成前就讀本機事件，
 * 重新整理後看不到另一台的紀錄；無限等則離線時會卡住。超時後同步仍在背景繼續。
 */
export function waitForSync(ctl, ms, timer = setTimeout) {
  return Promise.race([ctl.syncNow(), new Promise((resolve) => timer(() => resolve(null), ms))]);
}

/** 由設定組出 client；未設定回 null（GiteaStore 據此略過同步）。 */
export function clientFromConfig(cfg, fetchFn) {
  return isConfigured(cfg) ? makeGiteaClient({ ...cfg, fetchFn }) : null;
}

export function renderSyncSection(host, { config, onSave, onSyncNow }) {
  const c = config || {};
  host.innerHTML = `
    <div class="sync">
      <h3>同步（Gitea）</h3>
      <label>Gitea 網址 <input id="sync-url" type="url" placeholder="https://git.example.com" value="${esc(c.baseUrl)}"></label>
      <label>擁有者 <input id="sync-owner" value="${esc(c.owner)}"></label>
      <label>repo <input id="sync-repo" value="${esc(c.repo)}"></label>
      <label>token <input id="sync-token" type="password" autocomplete="off" value="${esc(c.token)}"></label>
      <button id="sync-save">儲存同步設定</button>
      <button id="sync-now">立即同步</button>
      <div id="sync-status" role="status"></div>
    </div>`;
  const val = (id) => host.querySelector(id).value.trim();
  host.querySelector('#sync-save').onclick = () =>
    onSave({ baseUrl: val('#sync-url'), owner: val('#sync-owner'), repo: val('#sync-repo'), token: val('#sync-token') });
  host.querySelector('#sync-now').onclick = () => onSyncNow();
  return { setStatus: (s) => { host.querySelector('#sync-status').textContent = s.text; } };
}

function esc(s) {
  return String(s ?? '').replace(/[&<>"']/g, (ch) => ({ '&': '&amp;', '<': '&lt;', '>': '&gt;', '"': '&quot;', "'": '&#39;' }[ch]));
}
```
